# 修复硬编码配置问题的计划

## 问题分析

当前代码中存在以下问题：
1. **硬编码的配置值**：在多个文件中存在硬编码的API密钥和配置值
2. **配置读取不一致**：部分配置从配置文件读取，部分直接硬编码
3. **安全性问题**：API密钥等敏感信息直接暴露在代码中

## 修复方案

### 1. 修改 ai_rtc_system.py

**当前问题**：
- 硬编码了默认的 app_key 和 access_key 值
- 当配置文件中没有值时，使用硬编码的默认值

**修复方法**：
- 移除硬编码的默认值
- 只从配置文件和环境变量中读取配置
- 添加明确的错误处理，当配置缺失时提供清晰的错误信息

### 2. 修改 tts.py

**当前问题**：
- 硬编码了默认的 appid 和 access_token 值
- 直接在代码中设置默认值

**修复方法**：
- 移除硬编码的默认值
- 只从配置文件和环境变量中读取配置
- 确保与其他模块的配置读取方式一致

### 3. 修改 stt.py

**当前问题**：
- 可能存在类似的硬编码问题
- 需要确保配置读取方式一致

**修复方法**：
- 检查并移除任何硬编码的配置值
- 统一使用配置文件读取配置

### 4. 完善配置文件

**当前问题**：
- 配置文件中的 API 密钥字段为空
- 缺少明确的配置说明

**修复方法**：
- 确保配置文件结构完整
- 添加配置说明和示例值
- 保持与代码读取逻辑的一致性

## 实施步骤

1. **分析现有代码**：详细检查所有相关文件中的硬编码配置
2. **修改配置读取逻辑**：更新代码以从配置文件读取所有配置
3. **移除硬编码值**：删除所有硬编码的 API 密钥和配置值
4. **测试配置读取**：确保修改后的代码能正确读取配置
5. **验证系统功能**：确保修复后系统能正常运行

## 预期效果

通过此修复，系统将：
- 不再包含硬编码的敏感信息
- 配置管理更加集中和一致
- 安全性得到提高
- 更容易维护和部署
