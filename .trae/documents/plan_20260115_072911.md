# 问题分析

经过进一步分析，我发现问题出在前端的消息处理逻辑中：

1. 在 `web_server.py` 中，无论是流式还是非流式处理，后端都会发送包含 `text` 字段的 `ai_text` 消息
2. 但是在前端的 `chat.js` 中，`handleWebSocketMessage` 方法处理 `ai_text` 消息时：
   - 只是调用了 `completeAIMessage()`
   - 没有使用消息中的 `text` 字段
   - 依赖之前累积的 `currentAIMessage`，这个值可能包含情绪标签

3. 另外，在流式处理时，`ai_text_chunk` 消息可能也会包含情绪标签，因为后端在发送chunk时的判断逻辑不够严格

# 修复方案

1. **修改前端的 `handleWebSocketMessage` 方法**：
   - 在处理 `ai_text` 消息时，使用消息中的 `text` 字段
   - 确保不依赖可能包含情绪标签的 `currentAIMessage`

2. **修改后端的流式处理逻辑**：
   - 在 `ai_conversation.py` 的 `get_response_stream` 方法中，改进情绪标签的过滤逻辑
   - 确保在发送chunk时完全不包含情绪标签

3. **具体修改点**：
   - 前端：修改 `vue3-frontend/src/stores/chat.js` 中的 `handleWebSocketMessage` 方法
   - 后端：修改 `ai_conversation.py` 中的 `get_response_stream` 方法

4. **验证步骤**：
   - 确保前端接收到的AI回复不包含情绪标签
   - 确保历史对话中不显示情绪标签
   - 确保情绪信息仍然正确传递

# 预期效果

修复后，系统将：
- 在所有情况下都正确移除情绪标签
- 不在前端显示或历史对话中包含情绪标签
- 保持情绪信息的正确传递
