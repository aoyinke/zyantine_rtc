# 修复异步生成器装饰器问题的计划

## 问题分析

通过分析代码，我发现了以下问题：

1. **异步生成器函数**：`ConversationManager.process_user_input_stream` 是一个异步生成器函数，使用 `async def` 定义并包含 `yield` 语句
2. **装饰器问题**：`@async_error_handler` 装饰器无法正确处理异步生成器函数
3. **类型错误**：装饰器返回的是一个普通的异步函数，而不是异步生成器函数
4. **调用错误**：当使用 `async for` 迭代时，期望得到可异步迭代的对象，但实际得到的是 coroutine 对象

## 修复方案

### 修改 error_handler.py

**当前问题**：
- `async_error_handler` 装饰器只适用于普通的异步函数
- 对于异步生成器函数，装饰器返回的函数使用 `return await func()`，这会返回 coroutine 对象
- 当使用 `async for` 迭代时会抛出类型错误

**修复方法**：
- 修改 `async_error_handler` 装饰器，使其能够正确处理异步生成器函数
- 对于异步生成器函数，装饰器应该返回一个新的异步生成器函数
- 使用 `async for` 迭代原始函数的结果并 `yield` 每个值
- 保持错误处理逻辑不变

### 具体修改点

1. **修改 `error_handler.py` 文件**：
   - 更新 `async_error_handler` 装饰器，使其能够检测并处理异步生成器函数
   - 对于异步生成器函数，返回一个新的异步生成器函数
   - 保持对普通异步函数的处理不变

### 修复效果

修复后，系统将：
- 能够正确处理异步生成器函数的装饰
- 保持错误处理能力
- 允许使用 `async for` 迭代装饰后的异步生成器函数
- 不再抛出类型错误
